# Review 3／3 — 平台证据、文档完整性与评分映射

审核视角：先看证据是否可查，再按"完成30/方法35/平台25/文档10"给分，最后检查有没有给自己多算分。

## 发现的问题

**F1（严重）平台证据以 UI 截图为主，控制台 stdout 是"手抄摘录"，不是导出日志。**
若评审要求原始日志，摘录会被视为不可核验。
处置：`docs/平台执行记录.md` 明确标注"stdout 为工作台控制台可见内容摘录，原始证据以截图为准"；截图 5 张随包提交（`platform/screenshots/`），画面里同时含脚本路径、运行状态与输出。

**F2（中）平台的"运行任务"模块没留独立截图。**
EVO 有「运行任务」入口，可作为第三次独立证据；本次只截了工作区编辑器内的控制台。
处置：作为已知短板登记（在平台维度扣分，不掩饰）。

**F3（严重）自评为"质量 60"，正好卡在 Q≥60 的线上。**
若评审在"完成"或"方法"维度再扣 2–3 分，交付直接无效（Q<60 → 不成立）。
处置：复核每一项的依据，确认没有虚高项；同时把可加固的地方补上（已补：时序口径、两臂重叠、code 路性质说明、无模型映射）；并在提交说明里主动说明"Q 处于临界，主要失分在仿真核验与敏感性扫描"。

**F4（中）价值 V 主张 0.80 与"OOS 未改善"存在张力。**
本实验对决策的改变是真实且可量化的（选型入口、风险上限字段、验收标准拆分），但任务的价值验收措辞包含"作用多大"，容易被读成"收益提升多大"。
处置：V 主张 0.80 的同时写清"若评审以组合收益改善为必要条件，建议 0.60"；两个积分都算出来（41 / 31），不藏着。

**F5（轻）文档里"IS 1215 + OOS 683"与"ALL 1899"并存，读者会算错。**
处置：已在 G1 说明，索引里也写了"2022-12-31 归 IS、不计入 OOS"。

**F6（轻）README 第 4 节 A 臂 ALL 回撤 −29.06% 大于 IS/OOS 各自回撤，看起来矛盾。**
实际是跨期拼接后回撤被放大，属正常。处置：不动数字，报告里说明"ALL 为跨期连续净值，回撤可大于子区间"。
